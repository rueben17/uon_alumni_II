## Why this stopped

The brief said:

> If the breaking-site list is more than the two known templates plus (at most) the two workaround sites, STOP and report before Step 2.

The enumeration found **a third breaking site**, and it is **outside the permitted Scope**:

**`apps/student/views.py:95`** — `StudentRegisterView.get_success_url()`

```python
        return reverse("all_uon_students")
```

A bare reverse with **no `urlconf=`**. At request time on `students.lvh.me`, `SubdomainRoutingMiddleware` sets `request.urlconf` from `SUBDOMAIN_URLCONFS['students']`. Today that is `apps.student.urls`, which registers no namespace, so the bare name resolves. Repoint it to `apps.student.site_urls` and the include becomes namespaced — the bare name then raises `NoReverseMatch`.

That is the **student registration success path**: a live 500 immediately after a student signs up. Scope permits `main/settings.py` (one line), `apps/student/urls.py` (`app_name` only), `apps/student/tests.py` and `templates/student/*.html`. It does **not** permit `apps/student/views.py`.

**Requested:** permission to add `student:` to that one reverse — `reverse("student:all_uon_students")`.

## Mechanism: does the staff mirror transfer?

**Yes, with one deliberate difference — `robots.txt`.**

`apps/staff/site_urls.py:12-13`:

```python
    path('robots.txt', TemplateView.as_view(template_name='robots.txt', content_type='text/plain'), name='robots_txt'),
    path('', include('apps.staff.urls')),
```

Staff serves `robots.txt` from `site_urls` because `apps/staff/urls.py` has no such route. **`apps/student/urls.py:13` already has one:**

```python
       path("robots.txt", TemplateView.as_view(template_name='robots.txt', content_type='text/plain'), name="robots_txt"),
```

Copying staff's shape literally would give the students subdomain two `robots.txt` routes — the unnamespaced one in `site_urls` shadowing the namespaced one in the include. Both serve the same template, so it would work, but it is redundant.

**Proposed:** omit `robots.txt` from `apps/student/site_urls.py` and let the include serve it at the same path, namespaced as `student:robots_txt`. The URL is unchanged at `/robots.txt`, and nothing reverses `robots_txt` anywhere — the enumeration found zero references. Removing the duplicate from `apps/student/urls.py` instead would mean editing that file beyond `app_name`, which Scope does not allow.

`app_name = 'student'` is **already present** at `apps/student/urls.py:5`, so no edit is needed there — the namespace registers as soon as the module is `include()`d.

Staff's other two entries have no student equivalent: `qr/` (`apps.qr_manager.urls`) and `qr-admin/` are staff-specific. The dev-only `static()` block at `staff/site_urls.py:29-30` **should** be mirrored, for the same reason — the middleware swaps the urlconf, so `main.urls`' static patterns do not apply on this host.

### Proposed `apps/student/site_urls.py`

```python
from django.conf import settings
from django.conf.urls.static import static
from django.urls import include, path

urlpatterns = [
    # Mirrors apps/staff/site_urls.py: the subdomain's root URLconf
    # include()s the app's own urls module, which is what registers its
    # app_name as a namespace. Pointing SUBDOMAIN_URLCONFS straight at
    # apps.student.urls (as it did until 2026-09-01) made it a ROOT
    # urlconf, and a root urlconf's module-level app_name registers
    # nothing -- so every 'student:' reverse raised NoReverseMatch.
    #
    # robots.txt is NOT repeated here, unlike staff's: apps/student/urls.py
    # already carries its own route for it, and the include serves it at
    # the same /robots.txt path.
    path('', include('apps.student.urls')),
]

# Dev-only: serve media on this subdomain too, same as staff's -- the
# middleware swaps the urlconf, so main.urls' static() patterns do not
# apply here. static() returns [] when DEBUG is False.
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

### The settings change — exactly one line, twice

`SUBDOMAIN_URLCONFS` is declared in both branches of the `if DEBUG:` block (`main/settings.py:415-420` and `:423-428`), with identical contents. The `'students'` mapping therefore appears **twice**:

```python
        'students': 'apps.student.urls',      ->      'students': 'apps.student.site_urls',
```

Both must change or dev and production diverge. That is two textual edits of the same one logical line. **Flagging explicitly**, since the brief specified "exactly ONE line" — no other line of `main/settings.py` would be touched.
