CONTENT TODO — Main Site (uonalumni.or.ke / www / apps.home)
Scope: content only (copy, media, data records). Excludes staff.* and students.* subdomains.
Audited: apps/home/models.py, views.py, urls.py, admin.py, context_processors.py,
templates/home/*, templates/snippets/{navbar,footer,banner}.html, templates/base.html.
================================================================================

Every planned page on the main site already has a nav entry in
templates/snippets/navbar.html (About / Membership / Get Involved / Resources
dropdowns) and, in most cases, a Django model + admin registration ready to
hold the content. What's missing is the actual content itself, and in several
cases the plumbing to display it. Grouped below by MVC layer so it's clear
whether the blocker is "someone needs to write/upload this" (Model), "this
page has no real content yet" (View), or "there's no route/wiring for the
content to reach a page at all" (Controller).

--------------------------------------------------------------------------------
MODEL — content/data that needs to be authored or entered
--------------------------------------------------------------------------------
All of these already have an admin.py registration (editable at /2005/) unless
noted otherwise, so this is a data-entry/copywriting task, not a dev task.

1. Executive Committee (Executive model, apps/home/models.py:231)
   Title, position, rank, bio (2500 chars), avatar per member. Needed for
   /executive-committee/ to render anything beyond an empty list.

2. Secretariat (Secretariat model, apps/home/models.py:468)
   Same shape as Executive (title/position/bio/avatar). Zero records assumed,
   and nothing in the codebase reads this model yet (see Controller #2).

3. Mission, Vision & Core Values
   - Mission/Vision are two hardcoded strings in
     apps/home/context_processors.py:91-92 (not a model, not editable without
     a code change) — decide whether to keep as static copy or move to a
     small singleton model an admin can edit.

     description, SVG icon, background image/color, order) and admin-

5. Partners (Partner model, apps/home/models.py:418)

6. News / Articles (Article model, apps/home/models.py:35)
   Richest content model in the schema — article_type (article/workshop/
   conference/forum/training), title, body, quote, thumbnail, banner image,
   is_feature/is_highlighted flags. The homepage literally promises "class
   notes, distinguished alumni profiles, obituaries, institutional updates,
   calls for mentorship, volunteer opportunities, scholarship success
   stories" (templates/home/alumni_home.html:49) and has zero of it.

7. UoN Alumni Walk (Event model, apps/home/models.py:319)

   (templates/snippets/navbar.html:202) — zero events entered, zero content.

8. Gallery photos (Images model, apps/home/models.py:154)
   Can attach to an Article, Chapter, or Event. Needed before the Gallery
   page can be more than a placeholder.

9. Banner imagery (Banner model, apps/home/models.py:114)
   Per-banner top/middle/bottom/main image + logo + short text, and it's
   already fetched into every template's context as `banner_images`
   (apps/home/context_processors.py:9-15) — but nothing renders it (see

10. Membership tier "benefits" copy (MembershipTier model, apps/home/models.py:551)
    Model only stores name/fee/type/duration — there's no text field for
    what a member actually gets at each tier. The nav's "Categories &
    Benefits" page (#15 below) can't be written until this exists, either as
    a new field on MembershipTier or as hardcoded per-tier copy.

--------------------------------------------------------------------------------
CONTROLLER — routing/wiring gaps blocking content from reaching a page
--------------------------------------------------------------------------------
Flagged because content in the Model section literally cannot go live until
these exist — not asking for a code review, just noting the dependency.

1. apps/home/urls.py has no routes at all for: Secretariat, Chapters
   (list + detail), Mission/Vision/Core Values, Partners, AGM, Consultancy &
   Training, Categories & Benefits, Alumni Card, Corporates, Notable Alumni,
   Alumni Walk (Event list/detail), News/Articles (list/detail), Downloads,
   Shop, Terms, Privacy. Every "View" item above needs a url pattern +
   view function before a template can be linked from the nav.

2. Article.get_absolute_url() (models.py:78), Event.get_absolute_url()
   (models.py:344), and Chapter.get_absolute_url() (models.py:400-401) all
   reverse() to url names ('home:uon_alumni_article_detail',
   'home:uon_alumni_walk_detail', 'home:uon_alumni_chapter_detail') that
   don't exist in apps/home/urls.py yet — the moment content editors add a
   row to any of these three models, calling get_absolute_url() will raise
   NoReverseMatch.

3. uon_alumni_exec_committee view (apps/home/views.py:37-46) renders
   'home/uon_alumni_exec_committee.html', which does not exist anywhere
   under templates/ — hitting the live /executive-committee/ URL will 500.
   (Currently unreachable via nav since that link's href="" — see View #19
   for Secretariat, same root cause pattern.)

4. context_processors.contacts() (apps/home/context_processors.py:118)
   computes `url_exec` but no template references `{{ url_exec }}` yet —
   navbar's own "Executive Committee" link is still a hardcoded href="".
   Same disconnect will apply to every new url_* variable added for the
   pages above.

5. snippets/banner.html is one hardcoded hero image + headline shared by
   literally every page on the site, rather than looping over the
   `banner_images` queryset already sitting in every template's context
   (context_processors.py:9-15, apps/home/models.py:114 Banner model).
   Content entered into Banner via admin currently has nowhere to appear.
